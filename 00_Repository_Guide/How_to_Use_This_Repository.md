# 🗓️ My Daily Learning Process

My normal learning process will be:

## Step 1: Learn the Concept

First, I will understand the basic concept.

I will try to answer questions such as:

- What is this concept?
- Why is it useful?
- Where can it be used?
- What problem does it solve?

---

## Step 2: Understand the Problem

Before writing code, I will carefully understand:

```text
Input
↓
Expected Output
↓
Constraints
↓
Edge Cases
```

I will first try to solve small examples manually.

---

## Step 3: Think About a Simple Solution

Before searching for an optimized solution, I will think about the most straightforward approach.

This helps me understand the problem better.

I will ask:

> If I had to solve this manually, what would I do?

This will usually lead to a basic or brute-force solution.

---

## Step 4: Improve the Solution

After understanding the basic approach, I will think about improving it.

Questions I will ask myself:

- Can I avoid repeated work?
- Can I use extra memory to save time?
- Can a HashMap or HashSet help?
- Can sorting help?
- Can I reduce the search space?
- Is there a common DSA pattern here?

---

## Step 5: Perform a Dry Run

Before writing the final code, I will test the logic manually.

For example:

```text
Input
  ↓
First Step
  ↓
Second Step
  ↓
Third Step
  ↓
Final Answer
```

A dry run helps me understand exactly what the algorithm is doing.

---

## Step 6: Write the Code

For important problems, I will try to implement the solution in:

```text
Python
Java
C++
```

The main goal is to understand that:

> The algorithmic logic remains similar even when the programming language changes.

---

## Step 7: Analyze Complexity

After solving the problem, I will analyze:

```text
Time Complexity
```

and:

```text
Space Complexity
```

I will try to understand why the complexity has that value instead of simply memorizing it.

# ⚠️ What I Will Do When I Get Stuck

Getting stuck is part of learning DSA.

When I cannot solve a problem, I will try this process:

```text
Understand the problem again
        ↓
Try a small example
        ↓
Think about brute force
        ↓
Identify repeated work
        ↓
Look for a useful pattern
        ↓
Learn the missing concept
        ↓
Try again
```

I will avoid immediately memorizing a solution.

My goal is to understand:

> Why does the solution work?

and not only:

> What code should I write?
